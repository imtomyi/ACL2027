# Synthetic dataset workspace

This page is the single records index for fictional data in the project.
Synthetic artifacts exist only to test software and data contracts. They are
not substitutes for source corpora, and neither their counts nor any experiment
or result derived from them may appear in a manuscript.

## KODIS demo workflow

Run from the repository root:

```bash
python3 dataset/scripts/prepare_kodis.py build \
  --input-root dataset/fixtures/kodis_synthetic/package \
  --adapter dataset/manifests/kodis_demo_adapter.json \
  --source-manifest dataset/manifests/kodis_demo_source_manifest.json \
  --split-manifest dataset/manifests/kodis_demo_split_manifest.json \
  --output Storage/synthetic-results/dataset-demos/kodis_demo \
  --demo --replace

python3 dataset/scripts/validate_kodis.py \
  --input-root dataset/fixtures/kodis_synthetic/package \
  --output Storage/synthetic-results/dataset-demos/kodis_demo \
  --adapter dataset/manifests/kodis_demo_adapter.json \
  --source-manifest dataset/manifests/kodis_demo_source_manifest.json \
  --split-manifest dataset/manifests/kodis_demo_split_manifest.json \
  --demo \
  --validation-report Storage/synthetic-results/dataset-demos/kodis_demo/validation_report.json \
  --replace-report

python3 -m unittest dataset/tests/test_kodis_pipeline.py
```

`../Storage/synthetic-results/dataset-demos/kodis_demo/` intentionally contains only four generated files.
The validator rejects extra files there, so documentation belongs on this page
rather than inside the output directory.

## Qualification-run layout

The completed run keeps each artifact class separate:

- `raw/`: immutable candidate generation records.
- `blinded/`: reviewer-facing bundles and their index.
- `judges/` and `paper_judges/`: supplementary blinded model assessments.
- root-level CSV/JSON files: validated long-form data, summaries, decisions, and inventories.
- `outputs/<task-id>/`: the generated review workbook and its inspection record.
- `workbook_previews/`: rendered workbook sheets used for visual verification.
- `RESULTS.md` and `PAPER_METRIC_RESULTS.md`: human-readable conclusions and limitations.

Do not move files out of the completed run: the manifest, inventories, and hashes
are part of its provenance. Add a new dated run for future qualifications.

## Naming and handling rules

- Use `*_synthetic` for source-like fictional fixtures, `*_demo` for generated
  pipeline demonstrations and their controls, and `*_synthetic_qualification`
  for complete experiment runs.
- Keep real source files under `raw/<corpus>/`; never place them in `fixtures/`.
- Keep synthetic outputs in their dedicated demo directory; never merge them
  with real de-identified outputs.
- Internal test reports derived from these artifacts must say **synthetic**,
  **fictional**, or **demo** in their title or immediate caption.
- Do not interpret synthetic proxy rankings as real-corpus model selection.
- Never include these datasets, experiments, results, tables, figures, or claims
  in a manuscript, appendix, compiled PDF, or submission export. A clear label
  does not make them manuscript-eligible.
- Never use them to replace a missing-result placeholder.
- Treat generated caches such as `__pycache__/` and `*.pyc` as disposable local
  clutter; they are not research artifacts.

## Real-data boundary

The real KODIS workbook is now present under restricted local handling and has
a separate private exploratory conversion; it is not a substitute for the
synthetic demo and does not clear the governed pipeline. The real CANDOR
distribution remains absent. The KODIS demo has zero
records eligible for experimental sampling. Real-data authorization, privacy
review, model-processing approval, and corpus-specific validation remain
separate gates documented in `KODIS_PROCESSING.md`, `CANDOR_PROCESSING.md`, and
the governance workspace.
