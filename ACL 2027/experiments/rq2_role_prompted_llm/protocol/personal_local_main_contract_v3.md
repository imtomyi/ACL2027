# RQ2 personal-local diagnostic execution contract v3

Status: active only for the separately frozen v2 qualification and diagnostic
runner. Every artifact is private personal exploratory material labeled
`private_personal_exploratory_not_for_publication` and
`diagnostic_not_manuscript_evidence`. No artifact, statistic, model outcome, or
claim from this path is eligible for a manuscript, submission, publication,
release, redistribution, or human-review workflow.

## Immutable predecessor boundary

The v1 runner, v1 freeze, and unsealed v1 run remain immutable historical
records. V2 imports verified v1 helper code but never resumes, mutates, copies,
pools, or analyzes a v1 outcome. It reads only the frozen source-free v1
development selection commitments so that the ten v2 development packets are
disjoint from the five v1 packets. V2 has a distinct freeze, run identifier,
output namespace, run contract, lifecycle ledger, completeness validator, and
seal.

The inherited personal-local boundary is unchanged. The only transport is the
numeric-loopback endpoint `http://127.0.0.1:11434`. Redirects, proxies, DNS,
cloud processing, retrieval, tools, and human review are disabled. The exact
policy, policy validator, readiness scope assessment, record hashes, split
index, model manifests, prompts, schemas, and runner hashes are checked before
source-bearing execution. Source-bearing artifacts remain below the private
Storage boundary and are never printed or copied into source-free summaries.

## Frozen development qualification

V2 begins with ten newly selected Dreaddit development packets. Their source
cluster commitments must be disjoint from the frozen v1 development
commitments. There is no adaptive packet replacement. V1 packets, items,
verifier decisions, and reviewer outcomes are excluded from every v2 count and
analysis.

Base generation uses six fixed evidence positions. Code maps positions to
opaque identifiers only after schema validation. A base must provide at least
two independent support units, a consequential countercase linked to a
boundary condition, and a context-only position proposed as a genuine
non-support candidate. A schema-valid base that fails these semantic rules is
quarantined. Its five precommitted variant slots are recorded as
`skipped_invalid_base`; none is generated, verified, replaced, or reviewed.

A separate target-free Gemma phase evaluates base admissibility using a compact
view containing only the six excerpts, mapped roles, and interpretation. A base
must be packet-bounded, warranted, free of outside facts and additional flaws,
and must retain the required support, countercase, boundary link, and
non-support candidate. `inadmissible`, `unclear`, or terminal base decisions
exclude all five dependent variant slots without replacement.

Three family candidates are assembled deterministically. Unsupported evidence
keeps the interpretation unchanged and promotes exactly the preverified
non-support position. Source concentration keeps the interpretation unchanged,
retains exactly one independent support unit, and demotes all other supports.
Counterevidence loss demotes one mapped countercase and deletes exactly its
linked boundary condition. Contextual flattening changes only one predeclared
qualification or distinction field. Unsupported abstraction changes only the
bounded claim. The latter two replacements are generated under narrow
position-aware schemas. Free-text construction notes and full-object variant
rewrites are forbidden.

The comparison verifier is target-blind. It receives the admitted compact base
and a machine-derived diff, not the target label, family index, construction
record, truth, reviewer output, or two duplicated full evaluator items. Code
accepts a candidate only when the comparison is clear, exactly the hidden
singleton target is present, no other material flaw is present, exactly one
material difference is present, and exactly one valid target anchor is
returned. A rejection, unclear decision, or terminal generation is never
regenerated, replaced, manually overridden, or cherry-picked.
Every comparison outcome is labeled
`frozen_local_model_screened_not_human_ground_truth`, exactly as bound by the
frozen comparison-acceptance rule.

## Qualification gate

The complete ten-by-five slot grid is reconciled before the qualification gate
is evaluated. At least eight of ten bases must be admitted, and at most two base
decisions may be `unclear`. Every assembled candidate must satisfy its exact
family diff signature. For every family, at most two of the ten planned
comparisons may be `unclear`, and at least five accepted candidates must come
from five independent packet clusters. Identity, integrity, unknown-position,
or deterministic-invariant failures fail the gate.

A terminal candidate-generation checkpoint is first quarantined and counted so
that the frozen grid remains auditable. The precommitted fatal-terminal rule
then fails qualification. This records the failure without a mid-grid crash,
replacement, hidden denominator, or downstream call.

If any threshold fails, V2 writes and seals a terminal
`qualification_failed` diagnostic. It performs no Llama review, fixed-role
selection, Dreaddit audit loading, or AGYW loading. No prompt, model, schema,
threshold, or packet is changed within that freeze. A different design requires
a separately frozen successor.

If every threshold passes, this qualification runner seals
`qualification_passed` and stops. It performs no reviewer call, fixed-role
selection, Dreaddit audit access, or AGYW access. A later v2-main execution may
proceed only under a separate prospective freeze that binds the passed
qualification gate and its seal, retains every frozen construction asset and
threshold without adaptation, uses only the accepted v2 development candidates
for review and fixed-role selection, and seals that selection before held-out
access.

## Lifecycle accounting and sealing

Every planned base and packet-by-family variant slot has one stable source-free
lifecycle row. The lane, packet index, family position, family name, slot
identifier, generation-call identifier, and verification-call identifier are
recomputed from the frozen grid. Ledger-provided identifiers are never trusted
as the source of an expected call set. For variants, the following identities
are mandatory:

```
planned = skipped_invalid_base + attempted
attempted = constructed + preverification_quarantined
constructed = verification_attempted
verification_attempted = verified + verifier_terminal
verified = accepted + verifier_valid_rejected
```

`attempted` means that the precommitted candidate slot was processed; actual
Qwen, Gemma, and Llama logical and physical call counts are reported
separately. `verified` means that the comparison verifier produced a valid
schema-conforming output, not merely that a call was started. Only accepted
variants are reviewed and analyzed. Every lane and family subtotal must
reconcile to the global funnel.

Completeness is derived from lifecycle states rather than from a fixed list of
successful items. Invalid bases require a base quarantine record and forbid
dependent calls. Every non-admitted base must have exactly five
`skipped_invalid_base` rows with no attempted, constructed, verified, or
accepted variant. An admitted base must have no skipped dependent row. Skipped
or terminal variants require quarantine records and forbid item, verifier, and
reviewer artifacts. Quarantine outcomes accept only their finite predeclared
reason-code sets. Constructed variants require their item, finite construction
record, verification input seal, and report. Accepted variants require one
qualification-truth record, while all reviewer calls and observations remain
forbidden in this freeze. Extra calls, second attempts, substituted packets,
unplanned items, missing terminal states, or acceptance/quarantine overlap
invalidate the seal.

Qualification-failed and qualification-passed runs both have exact
qualification-only inventories. Every qualification seal rejects reviewer,
fixed-role, audit, AGYW, and reviewer-performance artifacts. A passed gate is
only a prerequisite that a later separately bound v2-main freeze may cite. The
metric label remains
`automated-target recall among Gemma-screened variants`; it is never human
ground truth, confirmatory evidence, or manuscript evidence.
