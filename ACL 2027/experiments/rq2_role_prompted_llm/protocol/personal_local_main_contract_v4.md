# RQ2 personal-local final interface diagnostic contract v4

Status: active only for the separately frozen v2.2 development qualification.
Every artifact is private personal exploratory material labeled
`private_personal_exploratory_not_for_publication` and
`diagnostic_not_manuscript_evidence`. No artifact, statistic, model outcome, or
claim from this path is eligible for a manuscript, submission, publication,
release, redistribution, or human-review workflow.

## Immutable predecessor boundary

V2.2 imports the byte-bound v2.1 adapter, which in turn imports the byte-bound
v2 core and v1 helper runner. It does not alter any predecessor runner, freeze,
asset, run, checkpoint, gate, or seal. All predecessor results are excluded.
The source-free selection commitments shared by the prior v2 and v2.1 runs are
opened only during an authorized real-corpus execution and only to exclude
their sixty source clusters. The thirty v1 development commitments are also
excluded. No prior item, model output, label, threshold decision, or result is
reused.

V2.2 selects ten fresh Dreaddit development packets after both exclusion sets
have been applied. The ten packets are fixed without replacement. Their sixty
cluster commitments must be distinct from all ninety predecessor commitments.
The run has a separate identifier prefix, output directory, freeze snapshot,
interface contract, lifecycle records, terminal record, and output seal.

The inherited personal-local boundary is unchanged. The only model transport
is the numeric-loopback endpoint `http://127.0.0.1:11434`. Redirects, proxies,
DNS, cloud processing, retrieval, tools, and human review are disabled.
Source-bearing checkpoints remain under the private `Storage/` boundary and
are never printed.

## Serialization-only repair

V2.2 is the final repair of the base-admissibility structured-output
interface. Base generation, deterministic base construction, semantic
acceptance, the five construction families, comparison verification, and all
qualification thresholds are byte-bound to v2.1 or v2. The only construction
interface change is the serialization of the base-admissibility response.

The verifier returns one flat, fully required object. A deterministic adapter
checks the exact transport schema and the frozen cross-field conventions, then
rewrites the object to the original nested v2 admissibility representation.
The adapter changes no status, Boolean, readiness position, or reason code.
It only changes field layout and the schema-version marker. Unknown fields,
unknown codes, duplicate or out-of-range positions, contradictory status and
check combinations, contradictory readiness combinations, or any other
adapter-contract violation are format failures.

## Source-free live interface canary

Before a new run opens a predecessor selection, policy-bound record, corpus
file, split, or output artifact, it runs exactly three source-free Gemma calls.
The calls cover the admissible, materially flawed, and unclear transport
branches using the frozen canary fixtures. Each user prompt is exactly 16,384
ASCII bytes and contains no dataset, Storage, or evidence content. The model,
decoding, prompt, flat schema, and adapter are the same frozen interface used
by the real base-admissibility slots.

Each canary has one logical call and one physical attempt. Its response must
match the exact model and completed-stop contract, pass the flat schema, pass
the deterministic cross-field adapter, and convert to the exact frozen
canonical fixture. The runner neither writes nor prints a request, response,
status branch, readiness value, reason code, or model content. It carries
forward only a source-free pass count and evidence hash. A canary failure emits
one finite failure code and stops before data or output access, without retry.
An already sealed run validates its bound canary evidence hash without making
the three calls again.

## Format gate before semantics

All ten planned base-admissibility slots form one precommitted interface-format
denominator. A slot is format-valid only when base construction is available,
the one permitted verifier call has a valid transport response, the response
passes the flat JSON schema, and the deterministic adapter accepts every
cross-field convention. The gate requires exactly ten of ten format-valid
slots.

Before that gate passes, the runner does not call the semantic base-acceptance
function, create semantic base labels, write base-admissibility reports,
quarantine a base for a semantic decision, generate a variant, or invoke a
comparison verifier. Progress and gate output contain only source-free counts
and finite format-state codes. Restricted request and response checkpoints may
contain source-bearing input and the model's uninterpreted transport object,
and remain inside the sealed private run.

A format failure is terminal. The runner writes a source-free format gate,
terminal record, and output seal, then stops permanently. It performs no retry,
regeneration, packet replacement, manual override, variant call, comparison
call, reviewer call, fixed-role selection, Dreaddit audit access, or AGYW
access.

## Unchanged semantic qualification

Only after the ten-of-ten format gate passes does the runner expose the ten
deterministically adapted nested objects to the unchanged v2 semantic
base-acceptance function. It then uses the unchanged v2.1 prompts and schemas
for targeted edits and comparisons, the unchanged deterministic family edits,
the unchanged structural invariants, and the unchanged v2 qualification
thresholds.

At least eight bases must be admitted and at most two base decisions may be
unclear. Every family permits at most two unclear comparisons and requires at
least five accepted candidates from at least five independent packet clusters.
At least thirty candidates must be accepted overall. Terminal candidate calls
and deterministic invariant failures must both equal zero.

A semantic threshold failure is terminal and sealed without adaptation. A
qualification pass is also sealed and stops. Either outcome requires a
separate future freeze for any reviewer, fixed-role, Dreaddit audit, or AGYW
activity. The same v2.2 run can never continue after either outcome. Only a
qualification pass is eligible to be cited by a separately frozen future
execution. V2.2 itself never performs those operations.

## No adaptation or hidden denominator

Transport retries, semantic retries, regeneration, packet replacement, manual
override, cherry-picking, and threshold changes are forbidden. Each logical
model call has at most one physical attempt. A resume may only reconstruct an
existing successful checkpoint or seal an already terminal state. A sealed
format failure or semantic qualification outcome cannot be resumed.

Every printed message and every public gate, terminal, analysis, and seal
record is source-free. The final output seal inventories all private files and
binds the format gate. For semantic runs it also binds the unchanged
qualification gate and qualification analysis. Completeness validation rejects
reviewer, fixed-role, audit, AGYW, replacement, second-attempt, or unplanned
artifacts.

Seal creation, seal validation, and active resume require the complete frozen
v2.2 interface contract and the complete core run contract. The canary run
identifier, pass flag, and deterministic evidence hash must agree across both
contracts. Capability flags, predecessor hashes, packet and gate denominators,
labels, boundary checks, and source and eligibility declarations must equal the
freeze exactly. The source-free interface gate, format-failure analysis, and
terminal record use closed field sets. Their validators reject added fields,
changed continuation flags, inconsistent counts, and any recursively embedded
semantic status, readiness, reason, family, comparison, or qualification label.
The fresh-selection commitment artifact and every base-gate input seal are
also closed, type-exact, path-bound, and recursively label-free. Selection
validation requires ten ordered packets, six unique commitments per packet,
disjointness from all ninety predecessor commitments, and explicit nonreuse.
Each input seal binds its packet index, base and compact-view hashes, and the
canonical hash of the frozen flat transport schema. JSON validation treats
numeric and Boolean types as distinct even when the host language would compare
their values as equal.
