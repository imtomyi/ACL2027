# Qwen3 Generalist reviewer component contract v1

## Purpose

This component implements the Generalist review interface for WarrantRoute
with one exact local Qwen3 8B snapshot. It is an engineering component, not an
experiment. Its dry run and service canary use no corpus text and produce no
manuscript evidence.

The reviewer is a separate actor from candidate generation. A future study
freeze must identify the candidate-generation actor and must reject any packet
generated by this same reviewer actor. The component never constructs,
selects, edits, or verifies candidate outputs.

The component freeze is a local reproducibility binding, not an authorization
seal. No external approval record is attached to it. A future source-bearing
study must place the final component bundle digest in a separately approved
governance record that this component cannot rewrite.

## Input and output

The input is exactly one item conforming to
`direction-j-evaluator-item-v1`. The item contains the proposed
interpretation, displayed evidence, and source-coverage information. It must
not contain a target error, answer key, adjudication, route, generator
identity, construction note, cluster identifier, verifier output, or another
reviewer's response.

The output is exactly one object conforming to
`direction-j-shared-rating-v1`. A small transport schema constrains the JSON
object's fields and enumerated values during generation. The component then
validates the response against the complete shared schema, including all
numeric bounds and cross-field rules. It never assumes that the model service
enforced those semantic rules. Model identity, role, repetition, timing, and
token counts belong in a separate execution record. They do not enter the
actor-neutral rating object. The request disables tools and model thinking,
uses the frozen Generalist prompt and shared guide, and rejects input
truncation or context shifting.

## Frozen reviewer behavior

The reviewer actor is Qwen3 8B in the `reviewer` task role with the
`generalist` prompted role. It receives three independent, stateless calls
with seeds `2027082601`, `2027082602`, and `2027082603`. Repetition 1 is the
primary observation. Repetitions 2 and 3 support only the prespecified
stability analysis and never enlarge the item denominator.

A valid detection requires an empty `cannot_judge` list and the response-form
flag assigned to the independently verified error before evaluation. Invalid
JSON, schema failures, truncation, context overflow, timeouts, terminal
failures, abstention, `cannot_judge`, and a missing or wrong flag remain in the
denominator and count as misses. The component never retries, replaces an
item, changes models, or falls back to another service.

## Source-free commands

`dry-run` verifies the frozen files, hashes, reviewer identity, decoding, and
schema contracts. It does not contact the model service or open corpus files.

`preflight-service` verifies the numeric-loopback Ollama version, exact Qwen3
tag, and immutable digest. It does not submit an evaluator item.

`source-free-test` sends one inert in-memory interface canary through the same
prompt, request, response, schema, and context-accounting path. The canary is
software-test material only. It is not a dataset, experimental observation,
or manuscript result, and it is never written to disk by the component.
The only networked rating path in this component accepts the exact canonical
canary request. A schema-valid substitute item is rejected before a model call.

## Real-packet boundary

The `run` command is intentionally blocked. Enabling it requires a separate
authorized study freeze and runner that complete all governance checks before
opening a packet bank or contacting the reviewer. That freeze must bind:

- approved corpus, split, purpose, endpoint, retention, and release scopes;
- a privacy-cleared, sealed evaluator-item bank and a separate private truth
  map;
- a distinct candidate-generation actor and immutable actor snapshots;
- packet, prompt, guide, schema, scoring, runner, and analysis hashes;
- the target-to-flag mapping, fixed denominator, failure rules, cluster unit,
  and confidence-interval procedure;
- a clean held-out pre-access record and a complete final output seal.

Any missing, stale, or inconsistent gate stops before source access. Until a
complete authorized frozen export exists, Table 3 values remain explicit
placeholders.
