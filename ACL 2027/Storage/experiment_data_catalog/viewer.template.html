Common questions

Is this the same dataset as the earlier n100 experiment?

Yes. The current same-model WarrantRoute run reuses the same 400 packet IDs, claim texts and source excerpts as the earlier Generalist, Fixed role and All roles baseline evaluation. The loop implementation is new; the samples have not been replaced.

How were the 100 packets selected?

The stored n100 selection groups packet IDs by intended flaw, sorts each group and takes 20 per category. This is deterministic, flaw-balanced selection, not a random representative sample of all possible documents. ParlaMint's upstream source-turn sample used the fixed seed 20260901 before packet construction.

Are the four excerpts from the same person or conversation?

Not necessarily. A packet can combine different posts, comments, focus groups or parliamentary debates. Source and speaker IDs preserve provenance, but four excerpts do not imply four independent people. The 400 CaChe turns, for example, come from 11 focus-group transcripts.

What is the difference between the original labels and the flaw labels?

Dreaddit's original labels concern stress; GoEmotions' original labels concern emotions. Neither is a gold label for a flaw in the locally constructed claim. The experiment's truth map stores the builder's intended flaw, not independent human adjudication.

Can these results go straight into the paper?

Not under the current project policy. These already-used working packets contain controlled flaw templates, and nested construction fields can reveal intended flaws to reviewers. The quality judge removes those fields, but that cannot undo reviewer exposure. Independent human validation and an eligible evaluation design are still needed.

Packet content is read from the existing verified catalog. The source excerpts and constructed claims are preserved exactly. The packet explorer's linked reviewer files describe historical baseline outputs; the new WarrantRoute loop has its own frozen run record.

How a percentage is calculated

For either quality dimension, if a row has 100 binary judgments and 80 are true, the score is 80%. This is an illustrative calculation, not a result from this run.

A missing or genuinely unassessable judgment stays unresolved. It is not counted as false or silently removed from the denominator.

Who does what in the current loop?

Qwen-only

Qwen3 8B handles every agent role for all 400 packets.

Llama-only

Llama 3.1 8B handles the same roles for the same packets.

Gemma-only

Gemma 3 4B handles the same roles for the same packets.

Two initial reviews→Routed specialist reviews→Revision + owner recheck

Specialists are activated when the routing policy or an agent requests them. A packet can go through at most two revision rounds and 12 agent calls. The original issue owner, not the reviser, checks a proposed resolution.

The quality judge is separate. A fixed Qwen3 8B judge evaluates the original-claim review bundle, with model labels hidden. It does not score the final rewritten claim. Qwen judging Qwen reviews can still create self-family bias; these are not independent expert judgments.
Does "accepted" mean the document was successfully repaired?

No. Acceptance is the loop's internal stopping decision. It is not an independent measure of repair quality. Human escalation also does not by itself mean a software error; it can reflect unresolved issues or an exhausted revision budget.

What do the numbers in square brackets mean?

They are uncertainty intervals around detection recall, not the range of repeated scores for one packet. Historical baseline rows used Wilson intervals. The new loop scorer uses source-component bootstrap intervals, accounting for shared sources. Repeated excerpts or model calls are not additional independent samples.

Why can a table cell remain N/A?

A final quality percentage requires binary judgments for all 100 planned packets in that row. Missing initial reviews, technical failures or genuine evaluator abstentions remain unresolved. Their true, false and unresolved counts are kept separately; the experiment does not invent a value to fill the table.

Where does the answer sheet come from?

It is created with the packet, not found in the original dataset. The private truth_map.private.jsonl records the builder's intended defect in each locally constructed claim.

  1. Construct a claim with an intended flaw.The packet builders combine four source excerpts with a deterministic claim template for one of five flaw categories. They write the chosen category into both the packet and a separate truth record. This is an intended construction target, not proof that an expert would agree.
  2. Select the packet and its answer together.balanced_subset() sorts truth records by packet ID, groups them by intended flaw, and takes the first 20 records from each group. It retrieves the corresponding packets by exact packet_id and saves both subsets under sample_packets/balanced_n100/. This is deterministic selection, not a random draw or selection based on model performance.
  3. Keep the selected key bound to the run.The current run manifest records each selected packet file and truth file with SHA-256 hashes. All three model conditions reuse those same 100 packets per dataset. The scorer checks the bound truth file and looks up each trajectory by its packet ID.
  4. Match the intended category to a detected flag.For example, source_concentration maps to hidden_source_concentration. A detection counts when that flag occurs in the original-claim review flags. A generic complaint is not enough; additional flags do not by themselves invalidate a hit. This is target detection, not exact diagnosis matching or independent repair validation.
There is no human answer sheet for Credibility or Conformability here. Those are separate rubric-based judgments by Qwen3 8B over the review and supplied context. They are not obtained by looking up the intended flaw. Original stress or emotion labels are not flaw answers either.

The four selected answer sheets

Each packet in the Packet explorer also exposes its exact stored answer record. These records are for private inspection, not additional input to the agents.

Known limitation: earlier reviewer input sanitization removed top-level answer fields but retained nested construction metadata that can reveal the intended defect. A separate key file does not establish a fully blind evaluation. These remain private working diagnostics, not a human-validated benchmark.
